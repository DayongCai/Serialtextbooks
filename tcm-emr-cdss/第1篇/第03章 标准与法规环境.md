# 第3章 标准与法规环境

## 3.1 标准体系

### 3.1.1 病历与信息标准

通用侧的标准已经相对成熟，包括电子病历的功能规范与分级评价要求、医疗卫生信息系统的互联互通要求、以及病历书写与数据元相关的国家标准。中医电子病历必须落在这些框架内，而不是另立一套。

落地时的关键是映射：把中医要素映射到既有的数据元与文档结构中。映射表是项目最该维护的资产之一，它是"合规"与"可计算"之间的桥。

判断映射是否合格只有一个标准：能不能双向还原。只能单向映射的设计，会在数据回流时暴露问题。

> **要点**：映射是否合格的唯一判据是"能否双向还原"；只能单向映射的设计，会在数据回流时暴露。

**表3-1 相关标准与规范的定位（按名称引用，不臆造条款号）**

| 类别 | 代表性文件 | 管什么 |
| --- | --- | --- |
| 病历与功能 | 电子病历应用管理规范（试行）等文件 | 病历功能、时限、签名与分级评价 |
| 互联互通 | 医院信息互联互通标准化成熟度相关文件 | 跨系统数据交换的格式与语义 |
| 病证分类与代码 | GB/T 15657 中医病证分类与代码 | 病名与证候的分类与编码 |
| 临床诊疗术语 | GB/T 16751 中医临床诊疗术语 | 中医术语的规范表述 |
| 腧穴定位 | GB/T 12346 腧穴名称与定位 | 穴名、归经与定位 |
| 国际分类 | ICD-11 传统医学章节（第26章） | 传统医学病证的国际化分类 |

### 3.1.2 中医药术语与分类标准

中医药侧的核心标准包括中医病证分类与代码、中医临床诊疗术语、中药与方剂的编码规则，以及腧穴名称与定位相关的国家标准。这些标准给"同一事物用同一个名字"提供了依据。

需要注意版本：标准的修订会改变代码与名称，系统必须记录"这条数据依据哪个版本"，否则跨版本比较会出错。

另一个常见问题是"标准未覆盖"的临床实际用语。处理原则是：先如实保留原词，再标注映射到的标准词，**不允许为了对齐标准而改写医生的原始记录**。

> **要点**：标准修订会改代码与名称，因此每条数据都要记"依据哪个版本"；标准未覆盖的原词要保留，不许为对齐而改写医生记录。

## 3.2 法规约束与合规责任

### 3.2.1 数据安全与个人信息

病历数据属于敏感个人信息，处理必须遵循合法、正当、必要与诚信原则，并满足最小必要、目的限制、告知同意等要求。用于科研或教学时，需要额外的合规路径。

去标识化是常见手段，但必须承认它的局限：中医病历中的症状组合、方药特征在小样本下具有很强的可识别性，"去掉姓名"并不等于匿名。

因此制度上应当把去标识化后的数据仍按敏感数据处理，只是降低风险，不改变义务。

> **要点**：去标识化不等于匿名——症状组合与方药组合在小样本下就是指纹；去标识后仍按敏感数据管理。

**表3-2 合规要求与落地动作**

| 要求 | 含义 | 落地动作 |
| --- | --- | --- |
| 最小必要 | 只处理达成目的所必需的数据 | 为每个用途定义「用途—字段—期限」清单 |
| 目的限制 | 不得用于未声明的用途 | 用途变更须重新评估与授权 |
| 告知同意 | 患者知晓并同意处理 | 告知内容可理解，并提供可行的拒绝路径 |
| 去标识化 | 降低可识别性 | 去标识后仍按敏感数据管理，做重识别风险评估 |

<sub>表3-2　共 4 行 × 3 列 · 来源：据《数据安全法》《个人信息保护法》与医疗数据管理通行要求整理</sub>

### 3.2.2 医疗文书与责任

电子病历一旦生成，其修改必须留痕：谁改、何时改、改前改后是什么，都要可查。中医病历的"随证加减"尤其容易被事后修改，留痕机制是保障可追溯性的底线。

电子签名使记录具备法律效力，随之而来的是责任：系统给出的决策建议只构成"建议"，最终的诊断与处置权、责任仍在执业医师身上。

这一条在后面的决策支持部分会反复出现：**技术可以帮助判断，但不能代替担责**。

> **要点**：留痕要"界面可见"才算数，只写日志等于没有；技术可以帮判断，但不能代替担责。
